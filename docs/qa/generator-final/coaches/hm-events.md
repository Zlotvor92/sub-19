This separate review covers ten literal historical primary event replays, A (`f7bcbe9`) and B (`1a7571e`), followed by explicitly separate supplemental controls. No repository, other reviewer, user narrative, browser evidence or actual athlete outcome informed the judgments.

The primary evidence is the same frozen input sent to the old and new code. U01 replays each of two historical logs through both versions; comparisons hold the chosen log fixed. U05 uses a single identical historical plan/context payload for its primary goal change. The remaining primary cases use their explicit `cases.primary.inputSha256`. The JSON records hashes, dates, concrete day prescriptions before and after, correctness evidence, coaching judgments, supplemental scope and limitations.

A response can preserve data and reconcile arithmetic while still delivering an unsuitable race-preparation pathway. Conversely, a rejected regeneration can be a sensible response even though no new plan is produced. I evaluated the actual remaining schedule and decision text, not the success/error flag alone. Return percentages, minimum cycle lengths, readiness cutoffs and coverage thresholds are application heuristics. None establishes individual physiological clearance, and planned preparation is not completed preparation.

## Correctness, proof limits and sources

The reviewed primary regenerated cases show no arithmetic, session-description, prediction-index or protected-date failures in their audits. Old return cases separately contain stale stride descriptions/focus that those ordinary session-arithmetic checks do not catch; B repairs these. I inspected the relevant schedules and concrete changes rather than relying on empty failure arrays alone. U01 has no primary regeneration; U08 has primary rejection, so generated-plan claims are unavailable for both.

No elapsed seconds exist in U02/U03/U04/U07/U08 primary logs. Done/km/RPE entries cannot verify actual quality speed. U06/U09/U10 contain seconds for 8/18/13 synthetic completed entries respectively; U05 has 33 timed fixture entries totaling 106,931 seconds. These establish preservation of supplied numbers, not athlete performance validation. Historical prediction scalars/locks are not a new measured fitness test. Empty `measuredRowsChanged` arrays without a measured sentinel are vacuous for measurement preservation; separate explicit sentinels provide that limited proof. No source verifies server persistence, browser application, watch delivery, actual recovery or race success.

The coaching framework remains the publicly retrieved primary sources in the locked initial report: [B.A.A. Boston Half Training](https://www.baa.org/races/boston-half/info-for-athletes/boston-half-training/) supports individual adjustment and purposeful HM-specific practice; [Higdon Novice 1 Half Marathon](https://www.halhigdon.com/training-programs/half-marathon-training/novice-1-half-marathon/) supports conversational running and progressive endurance; [Higdon Novice 1 Marathon](https://www.halhigdon.com/training-programs/marathon-training/novice-1-marathon/) supplies a four-day counterexample to treating available days alone as the reason for marathon inadequacy. [Runna's public taper guidance](https://support.runna.com/en/articles/6576215-top-tips-for-tapering-before-a-race) advises against compensating for missed load near race day. These are comparators, not proprietary implementation claims or universal readiness thresholds.
