# Race split synchronization (v286)

The race AI flow now fetches activity details before opening a paid/quota-counted AI job. It works on previously imported activities and manually selected races, independent of the plan's training tag. Normal Strava/ICU synchronization also requests streams for race days and days with saved race context; ICU prioritizes those days within its three-stream request budget.

`activities.raceDetails(id, date, force)` fetches both connected sources. ICU uses activity streams and interval details; Strava uses activity details and streams, with `splits_metric` as the fallback. Missing cross-provider IDs are matched only when local date, distance and moving time agree and the candidate is unique. A conflicting date or incomplete distance coverage is rejected. Complete ICU splits are preferred; a complete Strava series can replace incomplete ICU data. Series are never concatenated or double counted.

`raceSplits` interpolates each distance boundary, weights sensors by elapsed time, keeps the last partial kilometer, and records moving and elapsed clocks separately. Without complete moving flags, pace is labeled as elapsed pace and pauses are unknown. Available pulse, cadence, power, elevation difference and sensor temperature are retained; coordinates and raw streams are excluded. The ICU proxy preserves false moving flags as zero.

Details are stored in the existing extensible log entry under `raceDetails`; no database migration is needed. Manual entries, notes, lock flags, training analyses and race context are preserved. Failed refreshes retain valid cached data for the same race date. Async writes check account generation, re-read the current log before committing, and deduplicate overlapping requests. Only a genuinely changed race split series releases the per-race analysis counter; server monthly quotas remain enforced. Superadmin functions and owner exceptions are unchanged.

The race panel offers “Osveži kilometarske prolaze” and a mobile table, including the partial last segment. Existing analysis is marked as outdated after new splits arrive; the user explicitly requests a new model analysis. Repeating a running AI job remains quota-free. If an imported race has no available splits, the flow reports the provider failure rather than opening an average-only job. A manual race without connected services can still be analyzed with its stated limitations.

The backend sends all bounded kilometer rows, source-labeled laps, source-specific supplemental summaries and ICU metrics to the model. It distinguishes official result, GPS distance, moving time and elapsed time. Morning wellness is labeled as preceding the race, not post-race recovery. The prompt requires concrete pacing observations and excludes VDOT conclusions from controlled or first-distance races. Model quality is not verified by mocked tests; these tests verify that the complete race data reaches the model boundary.

Validation includes stream math (sparse samples, stops, missing sensors, corrupt streams and partial kilometers), existing race backfill, both-provider fallback, incomplete/ambiguous activity rejection, preservation on failure, account changes, payload privacy, and browser flows for ICU streams and Strava metric splits through saved AI results and reloads.

## v287: one activity per race

Race imports (plan tag `trka` or saved race context) now choose the individual activity matching the race distance before aggregating metrics. A separate warm-up/cool-down is excluded from race distance, duration, weighted HR, elevation and pace. Ordinary training days retain the original multi-run aggregation. Race context distance takes precedence over the ordinary plan distance; a stale warm-up ID cannot override it. Missing or ambiguous race files do not overwrite the saved result.

Race details cache version 2 forces existing entries to be verified again. Explicit race refresh also repairs unlocked imported totals and removes the old merged-run marker, while preserving manual/locked data, notes, official result, context and analyses. Regression tests cover a 400m warm-up with a half marathon in both providers and ordinary-day aggregation.
